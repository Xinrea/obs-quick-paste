# Build infrastructure

Requires CMake 3.28+, a C++17 compiler, Qt 6 Core/Gui/Widgets, and the
**public OBS 32 libobs and frontend API SDK**. No OBS private UI headers are used.
Qt and OBS runtimes are not bundled with the plugin. Background work uses
QtCore's thread pool, so no QtConcurrent runtime is required.

## Qt-only tests

Use a complete Qt development installation with Qt Test (the official OBS Qt
dependency archive omits Qt Test):

```sh
cmake --preset tests -DCMAKE_PREFIX_PATH=/path/to/Qt/6.x/platform
cmake --build --preset tests --parallel
ctest --preset tests
```

On Ubuntu 24.04, `qt6-base-dev` and `ninja-build` suffice. This preset sets
`BUILD_PLUGIN=OFF`; OBS discovery and packaging are not executed. For another
generator, use `cmake -S . -B build/tests -DBUILD_PLUGIN=OFF -DBUILD_TESTING=ON`.
CTest uses the offscreen Qt platform plugin and never requires a running OBS.

## Reproducible macOS / Windows SDK

```sh
cmake -P cmake/BootstrapObs.cmake
cmake --preset macos-arm64 -C .deps/sdk-prefix.cmake
cmake --build --preset macos-arm64 --parallel
cmake --install build/macos-arm64 --config Release
```

Use `windows-x64` in place of `macos-arm64` on Windows (Visual Studio 2022).
This explicit bootstrap downloads the SHA256-pinned OBS 32.0.4 source release,
uses its official `buildspec.json` dependency pins (obs-deps / Qt 2025-08-23),
and builds/installs the public `Development` component, following the official
[OBS plugin template](https://github.com/obsproject/obs-plugintemplate).
All downloads, SDK builds, and installs stay under ignored `.deps/`.
Normal project configuration never downloads or builds OBS.

The bootstrap needs Xcode on macOS. To build Intel instead, use
`cmake -DOBS_ARCH=x86_64 -DDEPS_DIR=/path/to/separate/deps -P cmake/BootstrapObs.cmake`
and override `CMAKE_OSX_ARCHITECTURES=x86_64` when configuring the plugin. Do not
reuse one SDK build directory for different architectures.

## Existing public SDK / explicit fallback

The preferred integration is:

```sh
cmake -S . -B build/plugin -DBUILD_TESTING=OFF \
  "-DCMAKE_PREFIX_PATH=/path/to/obs-development-sdk;/path/to/obs-deps;/path/to/Qt"
```

This uses `find_package(libobs 32 CONFIG)` and
`find_package(obs-frontend-api 32 CONFIG)`. On macOS also include
`/path/to/obs-development-sdk/Frameworks` in `CMAKE_PREFIX_PATH` so CMake can find
the libobs framework's package, or set `libobs_DIR` directly to its
`Resources/cmake` directory. The bootstrap's generated cache handles this.

For an SDK without CMake package exports:

```sh
cmake -S . -B build/plugin -DBUILD_TESTING=OFF \
  -DOBS_SOURCE_DIR=/path/to/obs-studio-32.0.4 \
  -DOBS_BINARY_DIR=/path/to/configured-obs-build \
  -DOBS_SDK_DIR=/path/to/obs-binary-sdk \
  "-DCMAKE_PREFIX_PATH=/path/to/obs-deps;/path/to/Qt"
```

`OBS_SOURCE_DIR` supplies only public `libobs` and `frontend/api` headers.
`OBS_BINARY_DIR/config/obsconfig.h` must be generated by configuring matching
OBS sources; alternatively the SDK can supply `include/obs/obsconfig.h` or the
framework's `Headers/obsconfig.h`. Do not invent this generated header.
`OBS_SDK_DIR` supplies link libraries under `lib`, `bin/64bit`, or macOS
`Frameworks` / `Contents/Frameworks`. Windows requires import `.lib` files,
not only installed OBS DLLs. ARM builds also need the OBS dependency SDK's
SIMDe headers. Sources, generated headers, and libraries must match OBS 32 and
the target architecture; the fallback cannot validate binary ABI compatibility.

## Installation and packaging

`cmake --install` defaults to a staging directory inside the build tree when
using presets. Override `--prefix` explicitly to install elsewhere.

* macOS: `obs-quick-paste.plugin/Contents/MacOS/obs-quick-paste`, with locale data
  in `Contents/Resources/locale`. Copy the bundle into
  `~/Library/Application Support/obs-studio/plugins/`. The build is ad-hoc
  signed, not Developer ID signed or notarized.
* Windows: `obs-plugins/64bit/obs-quick-paste.dll` and
  `data/obs-plugins/obs-quick-paste/locale`. Merge these directories into the
  OBS installation root.
* Linux: standard `lib/obs-plugins` and `share/obs/obs-plugins/obs-quick-paste`
  destinations, configurable through GNUInstallDirs. CI validates only the
  Qt-only tests on Linux, not the Linux plugin.

Run `cpack -C Release -G ZIP -B packages` inside the configured build directory
for a portable archive. Use `-G NSIS` on Windows (NSIS 3.03+ required) for an EXE,
or `-G productbuild` on macOS for a current-user PKG. Native installers do not
bundle OBS/Qt or remove persisted images. Tag pushes matching the project version
publish installers, ZIP archives, and SHA256 checksums after all CI jobs pass;
branch/PR/manual builds only upload workflow artifacts. See
[the release procedure](../docs/building.md#ci-与验收) for signing limitations and
installation paths. Builds never install into the running user's OBS directory.
