# OBS Quick Paste

将系统剪贴板中的静态图片粘贴为**独立的 OBS 原生 `image_source`**。无需外部进程、网络服务或系统级键盘钩子。

> 当前版本 **1.0.0**，构建基线为 **OBS Studio 32.0.4 / Qt 6.8.3**，提供 Windows x64、macOS Apple Silicon 安装包。自动化测试不能替代聊天软件、OBS 前端及跨平台实机验收；请参阅 [验证记录](docs/testing.md)。

## 安装

从 [GitHub Releases](https://github.com/Xinrea/obs-quick-paste/releases) 下载对应平台的 `.exe` / `.pkg` 安装程序，或使用 ZIP 手动安装。安装前退出 OBS。Windows 安装程序与 macOS PKG 未进行发行者签名/公证；请核对 release 中的 SHA256，不要关闭系统安全保护。具体路径及升级/卸载说明见 [构建与安装](docs/building.md)。

## 使用

1. 安装插件并重新启动 OBS。
2. 从聊天软件、浏览器或截图工具复制图片，或者从文件管理器复制**一个本地静态图片文件**。
3. 在 OBS 主窗口的**预览、来源列表或场景列表**中按 `Ctrl+V`；macOS 使用 `Cmd+V`。
4. 图片保存为持久化 PNG，然后加入当前场景。Studio Mode 下目标为 **Preview**，不主动修改 Program 或触发转场。

每次粘贴创建新的文件、新的来源和新的场景项，不覆盖旧来源。图片保留透明度，默认居中、按画布的 80% 等比例缩小、小图不放大、置于最顶层并选中；支持原生移动、缩放、旋转、裁剪、滤镜、场景保存，以及 Undo / Redo。

### 不干扰原有操作

- 只有主窗口活动、焦点属于允许列表、剪贴板可解码为图片时才接管快捷键。
- 文本输入、来源重命名、设置/属性对话框、浏览器交互、浮动面板和未知控件保留原生行为；不把整个主窗口的空白区域都当成允许区域。
- OBS 复制来源使用内部剪贴板，**不会清空系统里的旧图片**。插件观察原生“复制来源”操作；此后保留来源粘贴，直到系统剪贴板再次变化或 OBS 在切换场景集合时清空内部剪贴板。
- 剪贴板无图片或插件被禁用时，原有 `QAction`/`QShortcut` 继续处理粘贴。持续按住按键不会批量创建来源，松开并再次按下可继续粘贴。
- 插件不改写系统剪贴板。只接受单张本地静态图片；不处理 GIF、动画、多文件、远程文件 URL。

## 设置及数据安全

通过 **工具 → 快速粘贴设置 / Quick Paste Settings** 配置：

| 设置 | 默认值 |
|---|---|
| 启用剪贴板图片粘贴 | 开启 |
| 自动居中 | 开启 |
| 最大画布占比 | 80% |
| 自动选中 | 开启 |
| 置于最顶层 | 开启；关闭时插入最底层 |
| 存储目录 | `obs_module_config_path("")` 下的 `images/` |
| 最大单边尺寸 | 16,384 像素 |
| 最大像素数 | 64,000,000 |
| 自动清理 | 关闭且不可启用 |

配置保存为插件配置目录中的 `config.json`。默认目录由 OBS 提供，支持 OBS 的普通/便携配置路径，不硬编码用户主目录。

文件名为 `quick-paste-<UTC timestamp>-<UUID>.png`。编码及磁盘写入在单个后台工作线程执行，通过同目录 `QSaveFile` 原子提交。只有保存成功后才在 UI 线程创建来源；失败会在 OBS 状态栏提示并写入 OBS 日志。最多同时接受 4 个待保存请求，快照总内存上限为 256 MiB。

切换场景、Preview、场景集合、配置文件或插件设置会取消尚未完成的请求。不会把先前捕获的图片误加到新场景。退出时停止接收请求并等待正在写入的文件，清除未创建来源的文件。

**不要删除可能仍被场景引用的图片。** 撤销、禁用插件、卸载插件和关闭 OBS 都不会删除已成功使用的图片。场景集合备份、其他场景、来源引用及撤销历史均可能需要它们，因此首版没有垃圾回收。更改存储目录不会移动旧文件；迁移 OBS 时应同时备份原图片目录。图片可能包含敏感内容，它们是本地明文 PNG，而非临时截图。

## 构建与安装

见 [构建说明](docs/building.md)，包括独立 SDK 构建、Windows/macOS 安装、仅运行 Qt 测试和签名限制。项目仅依赖 OBS 公开 SDK、Qt 6 和系统 C++ 工具链。

不要将 Anaconda Qt 5、MinGW Qt 或另一套自行打包的 Qt 动态库混入 OBS。发布包只含插件及本地化资源；OBS 和 Qt 运行库由宿主提供。修改插件后请重启 OBS，不支持热卸载/热重载。

## 设计与兼容边界

| 模块 | 职责 |
|---|---|
| `plugin-main` | 生命周期、工具菜单设置、有限队列、后台保存、UI 线程提交 |
| `paste-event-filter` / `paste-target` | `ShortcutOverride` 一次性认领、`KeyPress` 执行、严格焦点允许列表 |
| `clipboard-reader` | 原始像素 → 图片 MIME → 单个本地文件，尺寸限制、解码与快照 |
| `image-storage` | 持久化 PNG、唯一命名、原子提交 |
| `obs-source-factory` | RAII、场景/来源 UUID、创建与回滚、选择、Undo / Redo |
| `source-layout` | 目标场景真实画布尺寸下的纯布局计算 |
| `plugin-settings` | 设置默认值、校验、原子保存 |

### Qt 快捷键

应用级事件过滤器不是系统全局钩子。它在 `ShortcutOverride` 阶段读取并持有图片快照，明确接受事件以阻止 OBS 原生粘贴 QAction；随后对应的 `KeyPress` 只提交一次。仅监听 `KeyPress` 无法可靠避免原生 QAction 先消费快捷键。

OBS 没有公开的焦点区域识别或内部来源剪贴板查询 API。因此只通过 Qt 公共接口查找 `preview`、`sources`、`scenes` 及 `actionCopySource` **对象名**，不包含/链接任何 OBS 私有 C++ 类。它们仍是 OBS UI 的实现细节，升级时需要复核。如果原生复制 QAction 缺失，插件关闭拦截而不是冒险覆盖来源粘贴；未知焦点默认放行。

### 选择、画布及撤销

- 使用 `obs_sceneitem_select()`，而不是假设某个不存在的 `obs_sceneitem_set_selected()` 能同步 UI。OBS 32.0.4 的 `SourceTreeItem` 监听 `item_select` / `item_deselect` 并更新来源列表；代码级依据不代替实机观察。
- 布局使用目标场景的 `obs_source_get_canvas()` / `obs_canvas_get_video_info()` 的 `base_width`、`base_height`，不硬编码 1920×1080，也不把所有场景都假设为主画布。无法取得画布时停止创建。
- 布局使用捕获图片尺寸，不等待图片来源异步报告宽高。
- 通过 `obs_frontend_add_undo_redo_action()` 注册独立动作，存储场景 UUID、来源 UUID、场景项 ID 及恢复数据。撤销只移除目标场景项，不删除图片或其他地方引用的来源。回调带场景集合边界保护。
- OBS 没有公开 API 删除某个插件的撤销回调，所以插件仅支持正常的 OBS 进程生命周期，不支持在运行中卸载动态库。

## 非目标与待验收事项

不实现自定义渲染源、图片编辑器、OCR、剪贴板历史、云同步、图片上传、WebSocket、GIF 动画、批量粘贴或自动清理。Linux 可运行 Qt 自动化测试，但 Linux 插件发布和桌面剪贴板差异不在首期支持承诺内。

跨应用延迟剪贴板提供和图片解码仍可能发生在 UI 线程：只有确认可解码才允许接管快捷键。PNG 编码/写盘已移到后台，但不承诺超大图的解码毫无停顿。200ms 目标需按 [测试方法](docs/testing.md) 在目标系统上实测。
