# 测试与验收

## 自动化测试范围

Qt 测试不需要启动 OBS：

- `test-clipboard-storage`：原始图像与 MIME 优先级、QPixmap、独立快照、透明 PNG、单文件 URL、损坏/远程/多文件、GIF/APNG、像素限制、唯一文件名和保存失败。
- `test-paste-event-filter`：真实 Qt 焦点窗口 + 原生 Paste QAction，验证 `ShortcutOverride` 抢先接管、每次手势只创建一次、禁用/文本放行、OBS 原生复制后的旧图片抑制、编辑框、快照和自动重复。
- `test-source-layout`：不同图片/画布尺寸、80% 限制、原始比例、小图不放大、居中/原点及非法输入。
- `test-plugin-settings`：默认值、持久化、关闭自动清理、无效配置及路径。

这些测试没有伪装成完整 OBS 前端集成测试。尤其是目标场景创建、来源树选中、Undo / Redo 与 Studio Mode 仍需下面的实机步骤。

运行方法见 [building.md](building.md)。测试期间会修改测试进程所在会话的系统剪贴板；无头 CI 使用隔离的 offscreen/Xvfb 后端，避免覆盖桌面剪贴板。

## 实机前置条件

1. 使用备份或空白 OBS 配置/场景集合，不对正在直播的生产配置做测试。
2. 记录 OBS 完整版本、插件提交/构建标识、操作系统、CPU 架构、Qt 版本、画布/输出尺寸。
3. 安装插件并启动 OBS；确认日志中 `[obs-quick-paste] Loaded`，工具菜单有设置入口。
4. 准备透明 PNG、带方向信息的 JPEG、小图、超大图、损坏 PNG、GIF，以及一个已经存在的普通图片源。
5. 保存前后场景集合和日志；遇到错误时检查 OBS 状态栏及日志。

## 功能矩阵

以下每条分别在 Windows x64 与 macOS arm64 执行；macOS x86_64 单独记录，不推断为已通过。

| 操作 | 预期 |
|---|---|
| 聊天软件复制图片 → 来源列表粘贴 | 新标准图片源，来源面板独立一项 |
| 浏览器“复制图片” → 预览粘贴 | 新图片源，不以 HTML 文本代替 |
| 系统截图工具复制 → 场景列表粘贴 | 新图片源，透明度保留 |
| 同图按两次粘贴 | 两个独立来源、两个不同 PNG 文件 |
| 按住粘贴按键 | 不产生自动重复来源 |
| 小图/超大画布图 | 小图不放大；大图等比例缩小到 80% 范围并居中 |
| 移动/缩放/旋转/裁剪/滤镜/层级 | 与原生图片源行为一致 |
| 来源自动选中 | 来源列表高亮与预览变换框同步，可立即拖动 |
| 关闭自动选中 | 先前的选中状态保留 |
| 关闭置顶 | 新图位于底层 |
| 保存并重启 OBS | 图片仍可见，文件仍存在 |
| Studio Mode，Preview 和 Program 不同 | 只改变 Preview，不触发转场或改变 Program |
| 文件管理器复制单张图片 | 将图片另存为插件 PNG，不依赖原文件以后存在 |
| 复制多个文件、GIF、损坏图片 | 不创建来源、不拦截原生粘贴；不支持/错误提示可见 |
| 图片+文本同时存在 | 允许区域处理图片；文本编辑框只粘贴文本 |
| 仅文本 | 原有快捷键逻辑保持 |
| 复制来源（键盘、编辑菜单、右键菜单）后粘贴 | 原生来源粘贴，不粘贴系统剪贴板里的旧图 |
| 复制来源后再去外部复制图片 | 再次正常图片粘贴 |
| 属性/设置/交互窗口、来源重命名、可编辑下拉框 | 不拦截 |
| 浮动来源面板、不认识的控件 | 保守放行，不自动启用图片粘贴 |
| 其他应用粘贴 | 不受影响 |
| 禁用插件拦截 | 原生所有粘贴恢复 |
| 粘贴 → Undo → Redo → Undo → Redo | 单个场景项正确消失/恢复，同一来源 UUID，图片文件保留 |
| 粘贴后创建该来源的另一个引用，再撤销粘贴 | 不删除其他引用对应的来源或文件 |
| 撤销后切换场景集合 | 旧动作不影响新集合 |

## 错误、竞态及生命周期

- 将存储目录设为**测试目录**中的不可写位置或常规文件路径：保存失败，不新增来源，错误可见，无残缺 PNG。
- 用可丢弃的测试卷测试磁盘空间不足；不要填满生产磁盘。
- 粘贴超出单边/像素上限的图片：明确提示，不新增来源。
- 快速重复独立粘贴：队列有上限，每个成功请求各一张图，无覆盖。
- 在大图保存期间切换场景/Preview/Studio Mode/集合/配置：取消原请求，不向新目标插入。
- 在大图保存期间关闭 OBS：等待写入安全结束，无后台线程在插件卸载后执行；已使用图片不被删除。
- 在 Undo 后改变来源名称、删除目标场景、重复调用 Redo：不覆盖无关来源、不重复创建同一场景项。
- 多画布/非 1920×1080：对照目标场景的基础画布尺寸检查布局。

## 快捷键分发验证

自动化测试挂载一个真正的 Qt Paste QAction，而非直接调用 `paste()`；检查原生 QAction 触发次数和插件回调次数。实机上还需分别观察 Windows `Ctrl+V` 与 macOS `Cmd+V`：

1. 开启插件，复制有效图片并粘贴：只生成一项，不同时发生原生来源粘贴。
2. 禁用插件或用文本剪贴板：原生 QAction 保持有效。
3. 用系统菜单/窗口焦点切换、来源重命名、浏览器交互重复上述操作。
4. 若更新 OBS/Qt 后失败，先验证 UI 对象名与实际焦点对象；不要改成“拦截所有主窗口后代”。

## 性能

在 Release 构建下，用固定 1920×1080 RGBA 图片，记录键盘输入到来源可见的耗时，重复 30 次，报告中位数和 P95；同时记录 CPU、存储介质及是否后台录制。目标是常规图片尽量 <200ms，并非硬性通过条件。

另测试 4K、大尺寸上限附近图片；区分剪贴板提供/解码、PNG 编码、磁盘提交、来源加载耗时。确认空闲时没有周期性轮询、插件没有主动网络请求。
